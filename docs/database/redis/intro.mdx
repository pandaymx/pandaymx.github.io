# Redis 基础教程

Redis（Remote Dictionary Server）是一个极其快速的开源内存数据结构存储系统。它不仅可以用作数据库，还广泛用作缓存、消息中间件和会话存储。本文档面向初学者，介绍 Redis 的安装与五大基础数据结构操作。

## 1. Redis 简介

### 核心特性

- **纯内存存储**：读写速度极快，可达每秒十万级并发量。
- **丰富的数据结构**：不仅支持简单的 Key-Value，还支持 List、Set、Hash、Sorted Set 等。
- **持久化机制**：虽然是内存数据库，但可通过 RDB 和 AOF 将数据持久化到磁盘，防止断电丢失数据。
- **高可用与分布式**：原生支持主从复制、哨兵机制（Sentinel）和集群（Cluster）。

### Redis vs Memcached

虽然两者常被用作缓存，但 Redis 几乎在所有方面都更胜一筹：

- 数据类型：Memcached 仅支持字符串；Redis 支持丰富的数据结构。
- 持久化：Memcached 数据无法持久化；Redis 支持。
- 架构支持：Redis 原生支持集群模式。

### 适用场景

- 高并发场景的缓存层（如热点商品、页面缓存）。
- 分布式 Session 存储。
- 全局计数器（如点赞数、播放量）。
- 简单的消息队列（List/Stream）与排行榜（Sorted Set）。

## 2. 安装与启动

### Docker 快速启动

这是本地开发最推荐的方式：

```bash
# 启动 redis 容器并映射默认端口 6379
docker run -d --name my-redis -p 6379:6379 redis:latest

# 若需要设置密码启动
docker run -d --name my-redis -p 6379:6379 redis:latest redis-server --requirepass "mypassword"
```

### Linux 安装 (Ubuntu/Debian)

```bash
sudo apt update
sudo apt install redis-server
sudo systemctl start redis
```

### 客户端连接测试

使用 Redis 自带的命令行客户端 `redis-cli`：

```bash
# 连接本地 Redis
redis-cli

# 测试连接是否正常，正常会返回 PONG
127.0.0.1:6379> PING
PONG
```

## 3. 数据结构总览与基础操作

Redis 中的键（Key）永远是字符串，而值（Value）可以是五大基础数据结构之一。

### String (字符串)

最基本的数据类型，不仅可以存普通字符串，还能存整数用于计数，甚至存序列化后的 JSON 字符串（最大支持 512MB）。

```redis
# 设置和获取值
SET user:1 "alice"
GET user:1

# 批量操作
MSET k1 "v1" k2 "v2"
MGET k1 k2

# 计数器操作 (原子性，非常适合做阅读量统计)
SET page_views 100
INCR page_views       # 变为 101
DECRBY page_views 10  # 变为 91
```

### Hash (哈希)

类似一个小型字典，适合存储对象的不同字段。比起将整个对象序列化为 String 存储，使用 Hash 修改单个字段更加高效。

```redis
# 设置/获取单个字段
HSET user:100 name "bob" age 25
HGET user:100 age

# 批量设置/获取所有字段
HMSET user:101 name "char" email "c@test.com"
HGETALL user:101

# 给哈希里的数字字段增减
HINCRBY user:100 age 1
```

### List (列表)

按插入顺序排序的字符串链表。常用于最新消息流或实现简单的队列架构。

```redis
# 队头/队尾插入元素
LPUSH task_queue "task1" "task2"
RPUSH task_queue "task3"

# 队头/队尾弹出元素
LPOP task_queue
RPOP task_queue

# 获取一定范围内的元素 (0 是起始, -1 是最后一个元素)
LRANGE task_queue 0 -1
```

### Set (集合)

无序且不重复的字符串集合。常用于抽奖、打标签、计算交并补集等场景。

```redis
# 添加元素 (自动去重)
SADD tags "redis" "mysql" "redis"

# 查看所有元素
SMEMBERS tags

# 集合运算：交集 (找共同好友)
SADD user1:friends "A" "B" "C"
SADD user2:friends "B" "C" "D"
SINTER user1:friends user2:friends  # 返回 "B", "C"
```

### Sorted Set (有序集合 / ZSet)

类似 Set，不允许重复，但每个元素都会关联一个 `double` 类型的分数（score），集合按分数大小升序排列。常用于排行榜系统。

```redis
# 添加元素和它的分数
ZADD leaderboard 100 "alice" 150 "bob" 80 "char"

# 获取排名第一的用户 (按分数倒序排列)
ZREVRANGE leaderboard 0 0 WITHSCORES

# 增加某个元素的分数
ZINCRBY leaderboard 50 "alice"
```

## 4. Key 管理与过期机制

### 键的命名规范

通常使用冒号 `:` 分隔业务域和具体标识，以形成清晰的层级结构。例如：`app:users:1001:profile`。

### 过期时间设置

在缓存场景中，为键设置过期时间是必不可少的。

```redis
# 创建并直接设置 10 秒后过期
SET session_id "abcxyz" EX 10

# 为已有键单独设置过期时间 (秒)
EXPIRE session_id 60

# 查看剩余生存时间 (TTL: 返回正数表示剩余秒数，-1 表示永久，-2 表示已过期或不存在)
TTL session_id
```

### 遍历与删除键

```redis
# 删除键
DEL user:1

# 查找所有匹配前缀的键 (注意：KEYS 命令会阻塞 Redis，生产环境禁止使用！)
KEYS app:users:*

# 生产环境推荐使用 SCAN 渐进式遍历键空间
SCAN 0 MATCH app:users:* COUNT 100
```

## 5. 持久化基础简介

虽然本教程面向初学者，但了解 Redis 如何避免数据丢失非常重要：

- **RDB (快照模式)**：在指定时间间隔内将内存中的数据集快照写入磁盘。默认开启，适合大规模数据恢复。
- **AOF (命令日志模式)**：以日志的形式记录每一个写操作。数据安全性更高，但文件体积更大。
